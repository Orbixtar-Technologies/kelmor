# DNS

Each provisioned domain gets a zone file at `/var/lib/panel/dns/zones/<name>.zone` and default A/MX/SPF/DMARC records. A records use a globally routable `PANEL_PUBLIC_IPV4` when set. Private NIC addresses (RFC1918, Aliyun/AWS NAT) are not published — the installer and worker discover the EIP via cloud metadata or an HTTPS echo so Let's Encrypt does not reject the apex as “no valid A records”. Reconcile and certificate jobs rewrite existing private/`127.0.0.1` A records and SPF `ip4:` tokens. Operator-set public A records are left alone. PowerDNS listens on `127.0.0.1` and the local NIC (`local-address` in `pdns.conf`); the EIP is NAT, not a bind address. The HTTP API stays on loopback only (`127.0.0.1:8081`). The installer writes `/var/lib/panel/public.env` so the worker systemd unit publishes the same address.

Set `PANEL_PDNS_URL` and `PANEL_PDNS_API_KEY` on the worker to PATCH the live API after the zone file is written. Without those variables the file backend is still the source of truth for the agent.

DNSSEC uses the PowerDNS bind backend database at `/var/lib/panel/dns/bind-dnssec.sqlite3` (`bind-dnssec-db` in `pdns.conf`). Enabling DNSSEC on a zone queues `dns.dnssec`; the privileged agent runs `pdnsutil secure-zone` / `disable-dnssec` and `export-zone-ds`. Kelmor Control and `GET /dns/zones/{id}/ds` show the DS records to paste at the registrar. The HTTP cryptokeys API is not used — it does not work for bind-format zones.
